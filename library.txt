GPT를 이용한 라이브러리 정리

1. <sys/types.h> : 데이터 타입의 정의
이 헤더는 시스템에서 사용하는 **다양한 데이터 타입(Typedef)**들을 모아놓은 곳입니다.
역할: 시스템마다 int나 long의 크기가 다를 수 있기 때문에, 어떤 환경에서도 동일하게 동작하도록 표준화된 타입을 제공합니다.

주요 타입:
dev_t: 장치 ID (이미지 속 st_dev 등에 사용)
ino_t: inode 번호
mode_t: 파일의 권한 및 상태 설정값
off_t: 파일 크기나 오프셋 (바이트 단위)
pid_t: 프로세스 ID

2. <sys/stat.h> : 파일 상태와 권한
이름 그대로 **'File Stat(us)'**에 특화된 헤더입니다. 파일의 메타데이터를 다룰 때 필수입니다.
역할: 파일의 정보를 담는 struct stat 구조체 정의와 파일의 종류/권한을 확인하기 위한 매크로 상수들을 제공합니다.
주요 기능:
stat(), fstat(), lstat() 함수 선언
파일 권한 상수: S_IRUSR (소유자 읽기 권한), S_IWUSR (소유자 쓰기 권한) 등
파일 종류 확인 매크로: S_ISREG() (일반 파일인지?), S_ISDIR() (디렉터리인지?)

3. <unistd.h> : POSIX 운영체제 API
**'Unix Standard'**의 약자로, 유닉스 계열 운영체제(리눅스 포함)의 표준 서비스 인터페이스를 제공합니다.
역할: 시스템 호출(System Call)을 위한 가장 기본적인 함수들을 포함합니다. 운영체제에게 "이거 좀 해줘!"라고 요청하는 입구 역할을 합니다.
주요 기능:
파일 조작: read(), write(), close(), lseek()
프로세스 제어: fork(), exec(), getpid(), sleep()
표준 입출력 번호: STDIN_FILENO (0), STDOUT_FILENO (1), STDERR_FILENO (2)

💡 한눈에 정리하면?
헤더 파일	핵심 키워드	비유
<sys/types.h>	자료형	"어떤 그릇에 담을 것인가?"
<sys/stat.h>	상태/정보	"파일의 명찰(정보)을 어떻게 읽을 것인가?"
<unistd.h>	동작/명령	"파일을 읽고 쓰고 닫는 실제 행동"

4. <fcntl.h> : File Control
**'File Control'**의 약자로, 이미 열려 있는 파일의 속성을 변경하거나 파일을 열 때의 세부 옵션을 설정할 때 사용합니다.
역할: 파일 디스크립터(File Descriptor)에 대한 제어권을 가집니다. 파일이 열리는 방식(O_RDONLY, O_CREAT 등)을 정의하고, 실행 중인 파일의 설정을 바꿀 수 있습니다.

주요 기능:
open() 함수: 파일을 열 때 사용하는 시스템 호출.
fcntl() 함수: 이미 열린 파일의 플래그를 읽거나 수정 (예: 파일을 Non-blocking 모드로 변경).
파일 잠금(Advisory Locking): 여러 프로세스가 동시에 한 파일을 건드리지 못하게 F_SETLK 등을 사용해 잠금을 겁니다.

💡 unistd.h vs fcntl.h (헷갈리기 쉬운 점)
두 헤더 모두 파일 조작에 쓰이지만 초점이 다릅니다.
unistd.h: "파일을 읽어라(read) / 써라(write)" 같은 직접적인 동작 위주.
fcntl.h: "파일을 열 때 어떻게 열 것인가?(open) / 열려 있는 파일의 성질을 어떻게 바꿀 것인가?(fcntl)" 같은 상태 제어 위주.
